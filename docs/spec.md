# Cindra — спецификация

SaaS-платформа для AI-контента в соцсетях: пользователь задаёт тему/бренд-гайд, система генерирует тексты, изображения и видео, затем публикует их по расписанию в подключённые каналы.

**Статус:** MVP в разработке. Задачи — в Jira, доска [CIN](https://dalmonded.atlassian.net/jira/software/projects/CIN/boards/100).

Процесс разработки (git/Jira workflow) — см. `dev-workflow.md` в проекте [cindra](https://github.com/Newgate-Team) команды (шаблон, не привязан к конкретному репо).

## 0. Название

**Cindra** — рабочее название проекта.

## 1. Целевая аудитория и монетизация

**Целевая аудитория MVP (решено 2026-07-31):** SMM-агентства (несколько клиентских аккаунтов, нужны командные функции раньше, чем в исходном roadmap) **и** соло-предприниматели/крео (один бренд на пользователя). Оба сегмента входят в MVP — приоритет фич не сужается до одного профиля.

**Модель монетизации:** подписка (SaaS, тарифы/месяц).

**Открыто до старта биллинга** (гейт-тикет [CIN-18](https://dalmonded.atlassian.net/browse/CIN-18), блокирует [CIN-20](https://dalmonded.atlassian.net/browse/CIN-20)):
- Провайдер платежей (Stripe / ЮKassa / CloudPayments — зависит от гео пользователей).
- Есть ли free-тариф (freemium) или только trial.
- Юрисдикция пользователей.

## 2. MVP: платформы публикации (решено 2026-07-31)

Приоритет — **Telegram + Instagram**:
- **Telegram** — самый простой API, быстрый approval, доказывает пайплайн end-to-end быстрее всего.
- **Instagram** — охват целевой аудитории (и агентства, и соло-креаторы ведут клиентские/личные аккаунты именно там).

Остальные соцсети из первоначального списка (TikTok, YouTube, LinkedIn, Reddit, Twitter/X) — Phase 2/3 roadmap, не в MVP.

Задачи: эпики [CIN-5](https://dalmonded.atlassian.net/browse/CIN-5) (Telegram), [CIN-6](https://dalmonded.atlassian.net/browse/CIN-6) (Instagram).

## 3. Тип контента MVP (решено 2026-07-31)

**Текст + изображение + видео** — видео-генерация включена в MVP с первого дня (не вынесена в Phase 2, как рекомендовал первоначальный черновик спецификации). Это увеличивает сложность пайплайна генерации (эпик [CIN-4](https://dalmonded.atlassian.net/browse/CIN-4)), но закрывает больше юзкейсов сразу.

## 4. Архитектура репозитория

Монорепозиторий (обоснование: ранняя стадия, небольшая команда, единый CI/CD и общие контракты API между frontend и backend).

```
cindra/
├── apps/
│   ├── web/                 # Frontend — Next.js + TypeScript
│   └── api/                 # Backend — FastAPI + Python
├── packages/
│   ├── content-pipeline/    # Промпты, вызовы LLM/генеративных моделей, очередь задач
│   ├── social-integrations/ # Адаптеры публикации: Telegram, Instagram
│   └── shared-types/        # OpenAPI-контракт между web и api (генерируемые TS-типы)
├── infra/                   # docker-compose, деплой-конфиги, миграции БД
└── docs/                    # Спецификация, ADR
```

## 5. Технологический стек (решено 2026-07-31)

| Слой | Технология |
|---|---|
| Frontend | Next.js (React) + TypeScript |
| Backend/API | **Python (FastAPI)** — выбрано вместо NestJS |
| Очереди задач | **Celery + Redis** — Python-нативный эквивалент BullMQ (BullMQ специфичен для Node.js и несовместим с FastAPI-бэкендом) |
| БД | PostgreSQL |
| Генерация текста | Google Gemini 2.5 Flash-Lite API |
| Генерация изображений | Google Imagen 4 API |
| Генерация видео | Google Veo 3 Fast API |
| Хостинг | Vercel (frontend) + Railway/Render (backend) |

Frontend и backend на разных языках (TypeScript / Python) — контракт между ними держится через OpenAPI-схему FastAPI (автогенерация) → генерация TS-типов в `packages/shared-types` (например, `openapi-typescript`), а не через общий TS-код, как было бы при NestJS.

## 6. Компоненты системы

**Frontend (веб-интерфейс)**
Управление генерацией контента, календарь публикаций, подключение соцсетей (OAuth), просмотр/редактирование сгенерированного контента перед публикацией, биллинг/тарифы.

**Backend/API**
Оркестрация вызовов к генеративным моделям, бизнес-логика подписок и лимитов, очередь задач на генерацию и публикацию, аутентификация, хранение контента и метаданных.

**Пайплайн генерации контента**
Промпт-инжиниринг под тип контента (пост/сторис/видео-сценарий), вызовы к LLM (текст) и генеративным моделям (изображение/видео), модерация сгенерированного контента, повторные попытки при ошибках.

**Интеграции с соцсетями**
Модуль на каждую платформу (Telegram, Instagram): OAuth-подключение аккаунта, публикация по расписанию, обработка rate limits и ошибок API, статус публикации.

## 7. Метрики успеха MVP

- Time-to-first-post: сколько времени с регистрации до первой опубликованной публикации.
- Retention: доля пользователей, вернувшихся генерировать контент через 7/30 дней.
- Conversion в платный тариф (если есть free/trial).
- Стабильность публикаций: % успешных публикаций без ошибок API соцсети.

Задачи: эпик [CIN-9](https://dalmonded.atlassian.net/browse/CIN-9).

## 9. Оставшиеся открытые вопросы

- Провайдер платежей / free-tier / юрисдикция — см. гейт-тикет [CIN-18](https://dalmonded.atlassian.net/browse/CIN-18).

Границы тарифов подписки решены в [CIN-59](https://dalmonded.atlassian.net/browse/CIN-59), выведены из реальной себестоимости генерации на едином Google AI-стеке (Gemini 2.5 Flash-Lite / Imagen 4 / Veo 3.1 Fast) — полный расчёт в связанном юнит-экономика отчёте:

| Тариф | Текст/мес | Фото/мес | Видео/мес | Цена |
|---|---|---|---|---|
| Free | 20 | 3 | 0 | $0 |
| Pro | 300 (soft-cap) | 60 | 6 | $19 |
| Business | 600 (soft-cap) | 150 | 55 | $100 |

Лимиты — per-format (не единый счётчик "N генераций"): себестоимость текста/фото/видео различается на четыре порядка, единый лимит был бы либо слишком щедрым для видео, либо слишком тесным для текста. Реализация — [CIN-60](https://dalmonded.atlassian.net/browse/CIN-60).
