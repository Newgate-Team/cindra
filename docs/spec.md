# Cindra — спецификация

SaaS-платформа для AI-контента в соцсетях: пользователь задаёт тему/бренд-гайд, система генерирует тексты, изображения и видео, затем публикует их по расписанию в подключённые каналы.

**Статус:** MVP в разработке. Задачи — в Jira, доска [CIN](https://dalmonded.atlassian.net/jira/software/projects/CIN/boards/100).

Процесс разработки (git/Jira workflow) — см. `dev-workflow.md` в проекте [cindra](https://github.com/Newgate-Team) команды (шаблон, не привязан к конкретному репо).

**Cindra** — рабочее название проекта.

## 1. Целевая аудитория и монетизация

**Целевая аудитория MVP (решено 2026-07-31):** SMM-агентства (несколько клиентских аккаунтов, нужны командные функции раньше, чем в исходном roadmap) **и** соло-предприниматели/крео (один бренд на пользователя). Оба сегмента входят в MVP — приоритет фич не сужается до одного профиля.

**Модель монетизации:** подписка (SaaS, тарифы/месяц).

**Платежи (пересмотрено 2026-08-06, изначальное решение от 2026-08-04 по CloudPayments — см. историю ниже):**
- Провайдер: **PayPal** — глобальный процессор, не привязан к региону мерчанта (в отличие от CloudPayments). Stripe по-прежнему исключён — не поддерживает мерчантов из Казахстана.
- Юрисдикция регистрации компании — открытый вопрос (см. §9). Прежнее решение «Казахстан» было привязано к выбору CloudPayments и снято вместе с ним, отдельно не переподтверждалось.
- Free-тариф остаётся как реализовано в MVP (не только trial) — границы тарифов см. CIN-59 ниже.

**Глобальный запуск с первого дня (пересмотрено 2026-08-06):** PayPal не требует региональной верификации мерчанта, поэтому прежний план поэтапного выхода на рынки (сначала минимум 2 месяца только СНГ, затем остальной мир — было привязано к срокам верификации CloudPayments) снят. Доступность продукта не ограничивается по географии с момента запуска.

## 2. MVP: платформы публикации (расширено 2026-08-06, изначально решено 2026-07-31)

**Telegram + Instagram + Facebook** — все три платформы в MVP с первого дня:
- **Telegram** — самый простой API, быстрый approval, доказывает пайплайн end-to-end быстрее всего.
- **Instagram** — охват целевой аудитории (и агентства, и соло-креаторы ведут клиентские/личные аккаунты именно там).
- **Facebook** — тот же OAuth-флоу «Войти через Meta», что и для подключения Instagram, уже даёт доступ к управлению Facebook-страницей пользователя — публикация в неё добавлена как платформа без отдельной OAuth-интеграции.

**TikTok** — добавлен 2026-08-19 ([CIN-134](https://dalmonded.atlassian.net/browse/CIN-134)), вне первоначального плана: Login Kit + Content Posting API (Direct Post и Draft Upload). Единственная платформа только для видео — в матрице публикации ей доступен лишь `content_type=video`.

Остальные соцсети из первоначального списка (YouTube, LinkedIn, Reddit, Twitter/X) — Phase 2/3 roadmap, не в MVP.

Задачи: эпики [CIN-5](https://dalmonded.atlassian.net/browse/CIN-5) (Telegram), [CIN-6](https://dalmonded.atlassian.net/browse/CIN-6) (Instagram), [CIN-65](https://dalmonded.atlassian.net/browse/CIN-65) и далее (Facebook).

## 3. Тип контента MVP (решено 2026-07-31)

**Текст + изображение + видео** — видео-генерация включена в MVP с первого дня (не вынесена в Phase 2, как рекомендовал первоначальный черновик спецификации). Это увеличивает сложность пайплайна генерации (эпик [CIN-4](https://dalmonded.atlassian.net/browse/CIN-4)), но закрывает больше юзкейсов сразу.

**Пересмотр 2026-08-21 ([CIN-135](https://dalmonded.atlassian.net/browse/CIN-135)/[CIN-136](https://dalmonded.atlassian.net/browse/CIN-136)):** 8-секундный сгенерированный клип оказался слишком узким пониманием «видео» — публикуемый ролик обычно требует сценария, съёмки и монтажа. Приложение разделено на два раздела:

- **«Посты»** (`/generate`) — быстрый цикл: сгенерировал текст/изображение → опубликовал. Видео из него убрано.
- **«Видео»** (`/video`) — студия с проектным циклом: сценарий → выбор стиля → производственный бриф из трёх файлов (текст для начитки, что снять/сгенерировать, монтажный план) → готовый ролик. Ролик либо монтируется пользователем снаружи и загружается обратно, либо генерируется целиком стилем «Полное авто (Veo)». Для рисованных стилей студия сама генерирует иллюстрации брифа через image-пайплайн ([CIN-137](https://dalmonded.atlassian.net/browse/CIN-137)). Публикация в обоих случаях идёт через общий fan-out `/posts`.

## 4. Архитектура репозитория

Монорепозиторий (обоснование: ранняя стадия, небольшая команда, единый CI/CD и общие контракты API между frontend и backend).

Фактическая структура (актуализировано 2026-08-21 — от планировавшихся `packages/*` остались только пустые каталоги с README: пайплайн и интеграции живут пакетами внутри `apps/api/app/`, отдельные библиотеки на этом объёме кода только добавили бы сборочных швов; TS-типы поддерживаются вручную в `apps/web/lib/types.ts`, генерация из OpenAPI не вводилась):

```
cindra/
├── apps/
│   ├── web/                     # Frontend — Next.js + TypeScript
│   └── api/                     # Backend — FastAPI + Python
│       ├── app/
│       │   ├── routers/             # HTTP-эндпоинты (auth, content, posts, video_projects, …)
│       │   ├── content_pipeline/    # Промпты, вызовы генеративных моделей, очередь, модерация
│       │   ├── social_integrations/ # Адаптеры публикации: Telegram, Instagram, Facebook, TikTok
│       │   ├── billing_integrations/# PayPal
│       │   └── scheduler/           # Celery-задачи публикации по расписанию
│       ├── migrations/          # Alembic
│       └── tests/
├── infra/                       # docker-compose (Postgres, Redis)
└── docs/                        # Спецификация, юридические тексты
```

## 5. Технологический стек (решено 2026-07-31)

| Слой | Технология |
|---|---|
| Frontend | Next.js (React) + TypeScript |
| Backend/API | **Python (FastAPI)** — выбрано вместо NestJS |
| Очереди задач | **Celery + Redis** — Python-нативный эквивалент BullMQ (BullMQ специфичен для Node.js и несовместим с FastAPI-бэкендом) |
| БД | PostgreSQL |
| Генерация текста | Google Gemini 3.5 Flash-Lite API |
| Генерация изображений | Google Gemini 2.5 Flash Image (Interactions API) — заменил ранее выбранный Imagen 4, снятый с поддержки Google |
| Генерация видео | Google Veo 3.1 Fast API |
| Хостинг | Vercel (frontend) + Railway (backend) |

Frontend и backend на разных языках (TypeScript / Python) — контракт между ними планировалось держать через OpenAPI-схему FastAPI с генерацией TS-типов, а не через общий TS-код, как было бы при NestJS. По факту (2026-08-21) типы описаны вручную в `apps/web/lib/types.ts` и синхронизируются с `apps/api/app/schemas.py` глазами; на текущем объёме это дешевле генератора, но это осознанный долг — расхождение схем ловится только тестами и живой проверкой.

## 6. Компоненты системы

**Frontend (веб-интерфейс)**
Управление генерацией контента, календарь публикаций, подключение соцсетей (OAuth), просмотр/редактирование сгенерированного контента перед публикацией, биллинг/тарифы.

**Backend/API**
Оркестрация вызовов к генеративным моделям, бизнес-логика подписок и лимитов, очередь задач на генерацию и публикацию, аутентификация, хранение контента и метаданных.

**Пайплайн генерации контента**
Промпт-инжиниринг под тип контента (пост/сторис/видео-сценарий), вызовы к LLM (текст) и генеративным моделям (изображение/видео), модерация сгенерированного контента, повторные попытки при ошибках.

**Интеграции с соцсетями**
Модуль на каждую платформу (Telegram, Instagram, Facebook, TikTok): OAuth-подключение аккаунта, публикация по расписанию, обработка rate limits и ошибок API, статус публикации.

**Аутентификация**
Email + пароль и вход через Google ([CIN-133](https://dalmonded.atlassian.net/browse/CIN-133), Google Identity Services; у Google-аккаунтов пароля нет). Регистрация по email не подтверждает адрес (почтовой инфраструктуры нет), поэтому вход через Google по адресу, на который уже заведён парольный аккаунт, **отключает этот пароль** — иначе тот, кто первым занял чужой email, сохранил бы доступ к аккаунту владельца ([CIN-140](https://dalmonded.atlassian.net/browse/CIN-140)). Google в этот момент — единственная сторона, доказавшая владение адресом. Подключение Telegram-канала требует доказательства прав: одноразовый код в описании канала ([CIN-128](https://dalmonded.atlassian.net/browse/CIN-128)) — редактировать описание может только администратор.

## 7. Метрики успеха MVP

- Time-to-first-post: сколько времени с регистрации до первой опубликованной публикации.
- Retention: доля пользователей, вернувшихся генерировать контент через 7/30 дней.
- Conversion в платный тариф (если есть free/trial).
- Стабильность публикаций: % успешных публикаций без ошибок API соцсети.

## 9. Оставшиеся открытые вопросы

- Юрисдикция регистрации компании (см. §1) — прежнее решение «Казахстан» было привязано к выбору CloudPayments в качестве платёжного провайдера; после перехода на PayPal (не требует региональной привязки мерчанта) вопрос считается снова открытым, отдельного решения по нему не принималось.

Границы тарифов подписки решены в [CIN-59](https://dalmonded.atlassian.net/browse/CIN-59), выведены из реальной себестоимости генерации на едином Google AI-стеке (Gemini 3.5 Flash-Lite / Gemini 2.5 Flash Image / Veo 3.1 Fast) — полный расчёт в связанном юнит-экономика отчёте:

| Тариф | Текст/мес | Фото/мес | Видео/мес | Длинные AI-ролики/мес | Цена |
|---|---|---|---|---|---|
| Free | 20 | 3 | 0 | 0 | $0 |
| Pro | 300 (soft-cap) | 60 | 6 | 0 | $19 |
| Business | 600 (soft-cap) | 150 | 55 | 3 | $100 |

Лимиты — per-format (не единый счётчик "N генераций"): себестоимость текста/фото/видео различается на четыре порядка, единый лимит был бы либо слишком щедрым для видео, либо слишком тесным для текста. Реализация — [CIN-60](https://dalmonded.atlassian.net/browse/CIN-60).

**Длинные AI-ролики (добавлено 2026-09-02, [CIN-146](https://dalmonded.atlassian.net/browse/CIN-146)).** Колонка «Видео/мес» считает 8-секундные клипы Veo 3.1 Fast ($0.12/сек ⇒ $0.96 за клип). Seedance 2.5 ([CIN-144](https://dalmonded.atlassian.net/browse/CIN-144)) генерирует целый ролик со звуком одним вызовом, но стоит на порядок дороже — $0.473/сек в 720p, то есть ~$7.10 за 15-секундный ролик (длительность по умолчанию; максимум модели 30 сек стоил бы вдвое дороже). Поэтому у длинных роликов отдельный счётчик: включать их в общую видео-квоту нельзя — три десятка таких генераций стоили бы дороже годовой подписки. Business получает 3 в месяц (~$21 сверху к ~$60 остальной себестоимости при выручке $100), Pro и Free — ноль: один длинный ролик стоит дороже месячной подписки Pro.

Пока `FAL_KEY` не настроен, Seedance выключен и «Полное авто» генерирует через Veo, списывая обычную видео-квоту.
